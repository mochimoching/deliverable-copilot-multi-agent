# Issue #5562 要約: ジョブ起動失敗時に孤立した JobInstance が残る問題
## 概要
Spring Batch 6.0 で発生するリグレッション(バグ)です。ジョブ起動の途中で失敗しても、`JobInstance` だけが DB に残ります。メンテナーの fmbenhassine 氏は「意図した挙動ではなく、5.x からのリグレッション」と回答しています。マイルストーンは 6.1.0-RC1、状態は closed ですが、修正が実際に入ったかは入力から確認できません(提供された差分は `.gitignore` のみ)。報告環境は Spring Boot 4.1.1、Spring Batch 6.0.5、Java 25、H2 です。

## 問題
- 発端は、ジョブパラメータに `java.time.Year` を渡したところ `ConverterNotFoundException`(`java.time.Year` から `java.lang.String` への変換不可)が発生したことです。報告者は、この例外自体ではなく、失敗したのに `JobInstance` が永続化される点を問題にしています。
- 原因はトランザクション境界の違いです。
  - 5.x: パラメータを先に検証し、`JobInstance`、`JobExecution`、パラメータを単一トランザクションで作成する。失敗時は何も残らない。
  - 6.0: ランチャーが `JobInstance` を専用トランザクションで作成して即コミットし、その後にパラメータ検証と `JobExecution`・パラメータの作成を第2トランザクションで行う。最初のコミット後に失敗すると、実行履歴のない `JobInstance` が残る。
- 変換エラーに限らず、パラメータ検証エラーや永続化エラーでも同様に発生します。
- 残った `JobInstance` により、同一パラメータでの再起動が `IllegalStateException: Cannot find any job execution for job instance` で失敗します。incrementer を持つジョブの `startNextInstance` も妨げられます。
