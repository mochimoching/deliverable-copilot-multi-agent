# Issue #3757 要約: FlowJob 内でステップ名が重複した場合に警告ログを出す

## 概要

FlowJob の中に同名の別ステップがあると、実行時に WARN ログを出すようになりました。動作自体は変わらず、例外にもなりません。マイルストーンは 6.1.0-RC1 で、`backport-to-6.0.x` ラベルが付いています。

## 問題

- フロー定義の遷移は、ステップ名で次のステップを特定します。ステップ名は内部のマップのキーとしても使われます。そのため、ステップ名はフロー内で一意でなければなりません。
- issue の再現例では、条件付きフロー（`on("ODD")` や `on("EVEN")`）の step1〜step4 すべてに名前 "step1" を付けています。このジョブを実行すると、step3 付近で無限ループになります。
- ステップ名の重複はこれまで検知されず、原因の特定に時間がかかっていました。起票者によると、Spring Batch の初心者が間違えやすい点であり、この issue はそうした利用者を主に想定しています。
- XML 設定では、`<step>` の id がステップ名になり、xsd の制約で一意になります。

## 修正内容

変更対象は `FlowJob` と `FlowJobTests` です。

**検査のタイミング**
- `doExecute` の冒頭で `warnOnDuplicateStepNames()` を呼びます。
- 初期化時ではなく実行時に検査します。コード内コメントによると、ジョブスコープや step スコープのステップは、スコープが有効になって初めて名前を解決できるためです。
- 警告は重複した名前ごとに、FlowJob インスタンスの初回実行時に 1 度だけ出ます。ジョブを起動するたびには出ません。

**検査の範囲と重複の定義**
- 重複した名前を返す package-private のメソッド `findDuplicateStepNames()` を新設しました。
- ネストされたフロー（`FlowHolder`）も再帰的に検査します。
- 同名で別インスタンスのステップを重複とみなします。同一インスタンスを複数箇所で使う場合は重複とみなしません。

**出力**
- `logger.warn` で、次の趣旨の警告を出します。"Step name [X] is used by more than one step in job [Y]. Step names should be unique within a job: restart relies on them."
- 警告文は restart に言及しています。一方、issue 本文の症状は条件付きフローでの無限ループです。両者の因果関係は、入力からは判断できません。

**内部の変更**
- ステップの登録処理を、重複を集める形に変更しました。あわせて、旧コードで `StepHolder` の分岐が引数の `map` ではなく `stepMap` に直接書き込んでいた点も直っています。
- 警告のみで、動作は変えません。`stepMap` に同名のステップが入ると、後のものが前のものを上書きする挙動は残ります。

## 利用者への影響・対応

- 既存ジョブの動作は変わりません。同名の別ステップがあれば、重複した名前ごとに、FlowJob インスタンスの初回実行時に 1 度だけ警告します。
- 同名の別インスタンスを使っている既存ジョブは、意図的であっても警告が出るようになります。ステップ名を変更する場合は、警告文のとおり restart がステップ名に依存するため、restart や既存の実行履歴への影響を確認したうえで行ってください。改名が安全かどうかは、資料からは判断できません。
- 同一インスタンスを複数箇所で使う分には、問題ありません。警告も出ません。
- WARN ログが新たに出力されます。

## 補足

**テスト**（`FlowJobTests` に 3 件追加）
- `testDuplicateStepNamesAreDetected`: 別インスタンスの同名ステップを検出する。
- `testDuplicateStepNamesAreDetectedInNestedFlows`: ネストされたフロー内の同名ステップを検出する。
- `testSameStepInstanceUsedSeveralTimesIsNotADuplicate`: 同一インスタンスの再利用は重複としない。
- これらが確認するのは検出ロジックのみです。ログ出力と 1 回限りの挙動は、テストの対象外です。
